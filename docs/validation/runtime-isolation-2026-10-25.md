# Изоляция gRPC runtime — 25 октября 2026

## Изменение

Execution-команды Nautilus rc7 выполняются через его глобальный runtime.
До исправления tonic-канал создавался в runtime вызывающего приложения.
При однопоточном host runtime синхронная работа приложения могла останавливать
сокет, буфер канала и HTTP/2-задачи уже подготовленного execution-запроса.

Теперь `connect_channel` создаёт соединение в `get_runtime()` Nautilus.
Владение остаётся у `TbankSession`; клиенты продолжают использовать один общий
канал. Временная connect-задача принадлежит `JoinSet` и отменяется вместе с
незавершённым подключением. Схема ордеров, request ID и правила восстановления
не менялись.

Добавлены диагностические стадии `SubmitOrder.command_task_started` и
`SubmitOrder.preflight_finished` между получением команды и транспортными
стадиями. Они дополняют диагностику, не подтверждая принятие ордера брокером.

## Воспроизводимое подтверждение

`grpc::channel::tests::channel_progresses_when_caller_runtime_is_blocked`
поднимает mock-брокер и command worker в runtime Nautilus, прогревает канал,
затем блокирует вызывающий однопоточный runtime.

- До исправления RPC не завершается за двухсекундное контрольное окно.
- После исправления RPC завершается во время блокировки host runtime.

Это проверка независимости сетевого обслуживания от host-потока. Она не
измеряет выигрыш на боевом брокере и не доказывает улучшение места заявки.

## Выполненная валидация

- `cargo test --locked`: 580 unit-тестов и offline integration-тесты прошли.
- `cargo test --locked --all-features`: 580 unit-тестов и offline integration-тесты прошли.
- `cargo clippy --locked --lib -- -D warnings`: прошёл.
- Полный серийный `sandbox_integration -- --ignored --test-threads=1 --nocapture`:
  **4 passed, 1 failed**, один capability-тест filtered.

Упал `sandbox_market_fill`: восстановление fill history получило операцию со
сделкой без канонического broker order ID и отказалось возвращать частичный
результат. Строгая проверка идентичности не ослаблялась. Cleanup завершился без
ошибки; последующее read-only чтение показало 1 единицу бумаги, 0 активных
обычных заявок и 0 активных стоп-заявок. Это не подтверждение нулевой позиции.

Повторный mutating-прогон вслепую не выполнялся. До полной приёмки требуется
разобрать отсутствующую идентичность исторической операции и повторно выполнить
полный sandbox-набор в контролируемом состоянии. Текущий результат **не является
успешным полным sandbox acceptance**. Боевые диагностические прогоны потребителя
не заменяют эту проверку.
